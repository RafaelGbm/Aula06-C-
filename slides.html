Por que criar CriarProdutoInput?

Contrato da operação
public sealed class CriarProdutoInput
{
    public string Nome { get; init; } = string.Empty;
    public string Categoria { get; init; } = string.Empty;
    public decimal Preco { get; init; }
    public int Estoque { get; init; }
}

Hot Chocolate infere o input GraphQL a partir dessa classe.

Por que não receber Produto?
  • A entidade também possui Id, Ativo e relacionamentos.
  • O cliente controlaria campos que pertencem ao servidor.
  • Uma mudança no banco poderia alterar a API sem intenção.
  • Create e update normalmente aceitam campos diferentes.
A entidade representa persistência; o input representa a intenção de criar um produto.

O resolver persiste a mudança

public async Task<CriarProdutoPayload> CriarProdutoAsync(
    CriarProdutoInput input,
    AppDbContext db,
    CancellationToken cancellationToken)
{
    Produto produto = new()
    {
        Nome = input.Nome.Trim(),
        Categoria = input.Categoria.Trim(),
        Preco = input.Preco,
        Estoque = input.Estoque
    };

    db.Produtos.Add(produto);
    await db.SaveChangesAsync(cancellationToken);

    return new CriarProdutoPayload { Produto = produto };
}

O identificador é preenchido após SaveChangesAsync.

O tipo Mutation precisa entrar no schema

builder.Services
    .AddGraphQLServer()
    .AddQueryType<Query>()
    .AddMutationType<Mutation>()
    .AddProjections()
    .AddFiltering()
    .AddSorting();

Criar a classe sem chamar AddMutationType<Mutation>() não expõe a operação.

Mutation nomeada com variável

Operação
mutation CriarProduto($input: CriarProdutoInput!) {
  criarProduto(input: $input) {
    produto {
      id
      nome
      preco
    }
  }
}
Variáveis
{
  "input": {
    "nome": "Webcam 4K",
    "categoria": "Vídeo",
    "preco": 799.90,
    "estoque": 4
  }
}

Como comprovar a escrita

Estado inicial

Execute produtos e observe os dados atuais.

Mutation

Crie o produto e capture o identificador retornado.

Nova leitura

Consulte pelo identificador ou nome e confirme a persistência.

Valide antes de escrever no banco

Regra mínima
  • Nome não pode ser vazio.
  • Preço deve ser maior que zero.
  • Entrada inválida não chega ao banco.
Implementação em C#
if (string.IsNullOrWhiteSpace(nome))
{
    throw CreateError(
        "Informe o nome do produto.",
        "PRODUTO_NOME_INVALIDO");
}

if (input.Preco <= 0)
{
    throw CreateError(
        "O preço deve ser maior que zero.",
        "PRODUTO_PRECO_INVALIDO");
}

Docker em três ideias

Dockerfile

Receita versionada para construir a aplicação.

Imagem

Pacote imutável com aplicação e dependências.

Contêiner

Processo em execução criado a partir da imagem.

Docker não é o deploy desta aula; é apenas outra forma de executar a mesma API.

Leia somente as instruções essenciais

FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:10.0
WORKDIR /app
COPY --from=build /app/publish .
EXPOSE 8080
ENTRYPOINT ["dotnet", "LojaGraphQL.Api.dll"]

sdk compila; aspnet executa. A imagem final não precisa carregar o kit de desenvolvimento.

O que acontece com o banco?

Durante a execução

A mutation grava no SQLite e a query encontra o novo produto.

Após remover o contêiner

O arquivo local é descartado porque nenhum volume foi configurado.

Volumes são importantes, mas não são necessários para o objetivo desta aula.
