GraphQL

Criar as classes de entrada e saída

Dependência

A operação de criação precisa receber somente os campos permitidos ao cliente e devolver o produto criado.

Implementação solicitada

  1. Criar GraphQL\Mutation.cs.
  2. Criar a classe CriarProdutoInput com nome, categoria, preço e estoque.
  3. Criar a classe CriarProdutoPayload contendo o produto criado.

Critérios de aceite

  • O projeto compila.
  • CriarProdutoInput não contém Id, Ativo ou relacionamentos.
  • CriarProdutoPayload contém uma propriedade Produto.

Validação

dotnet build

GraphQL

Expor a mutation no schema

Dependência

Concluir LAB-001.

As classes de entrada e saída existem, mas o schema ainda não oferece uma operação de escrita.

Implementação solicitada

  1. Criar a classe pública Mutation.
  2. Criar CriarProduto, recebendo CriarProdutoInput.
  3. Montar um objeto Produto com os dados do input.
  4. Retornar CriarProdutoPayload sem acessar o banco neste ticket.
  5. Registrar .AddMutationType<Mutation>() depois de .AddQueryType<Query>().

Critérios de aceite

  • O schema possui o tipo raiz Mutation.
  • O campo criarProduto recebe um único argumento input.
  • O retorno possui o campo produto.
  • A operação ainda não promete persistência.

Validação

Abrir a documentação do schema no Nitro, localizar Mutation e confirmar o campo criarProduto.

C# e EF Core

Persistir um produto válido

Dependência

Concluir LAB-002.

A mutation já aparece no schema, mas o produto retornado ainda não é salvo no banco.

Implementação solicitada

  1. Tornar CriarProduto assíncrono.
  2. Receber AppDbContext e CancellationToken.
  3. Adicionar o produto a db.Produtos.
  4. Chamar SaveChangesAsync(cancellationToken).
  5. Retornar o payload somente depois da persistência.

Critérios de aceite

  • Uma entrada válida retorna identificador maior que zero.
  • O registro permanece no banco após o fim da mutation.
  • O CancellationToken é repassado ao EF Core.

Validação

Executar CriarProduto de operacoes.graphql e observar o identificador retornado.

Referências

  • Entity Framework Core — salvar dados
  • Entity Framework Core — APIs assíncronas
Validação

Rejeitar entradas inválidas

Dependência

Concluir LAB-003.

A mutation persiste qualquer valor recebido. O servidor precisa impedir dados inválidos antes de chamar o banco.

Implementação solicitada

  1. Remover os espaços externos do nome.
  2. Rejeitar nome vazio com o código PRODUTO_NOME_INVALIDO.
  3. Rejeitar preço menor ou igual a zero com o código PRODUTO_PRECO_INVALIDO.
  4. Executar as validações antes de db.Produtos.Add.

Critérios de aceite

  • Nome em branco retorna erro legível.
  • Preço inválido retorna erro legível.
  • Nenhuma entrada inválida é persistida.

Validação

Executar RejeitarPrecoInvalido e RejeitarNomeInvalido de operacoes.graphql.

GraphQL

Comprovar a escrita com uma query

Dependência

Concluir LAB-004.

O payload informa o resultado da mutation, mas uma nova leitura comprova que o estado do sistema realmente mudou.

Implementação solicitada

  1. Executar a mutation válida.
  2. Copiar o identificador retornado.
  3. Executar produtoPorId usando esse identificador.
  4. Comparar os dados da mutation com os dados da query.

Critérios de aceite

  • A query encontra o produto criado.
  • Nome, categoria, preço e estoque correspondem ao input.
  • O fluxo pode ser repetido no Nitro.

Validação

Executar CriarProduto e depois ConfirmarProduto de operacoes.graphql.

Docker

Executar a aplicação em um contêiner

Dependência

Concluir LAB-005.

A aplicação já funciona com dotnet run. Agora ela deve funcionar da mesma maneira a partir de uma imagem.

Implementação solicitada

  1. Ler o Dockerfile e identificar as imagens de build e runtime.
  2. Construir a imagem com a tag loja-graphql:aula07.
  3. Criar o contêiner mapeando a porta 8080.
  4. Abrir /graphql e executar o fluxo write-then-read.
  5. Consultar os logs e parar o contêiner.

Critérios de aceite

  • A imagem aparece em docker images.
  • O contêiner aparece em docker ps.
  • http://localhost:8080/graphql responde.
  • A mutation e a query funcionam dentro do contêiner.
  • Os logs mostram a aplicação escutando na porta 8080.

Validação

docker build -f .\LojaGraphQL.Api\Dockerfile -t loja-graphql:aula07 .
docker run -d --rm --name loja-graphql-aula07 -p 8080:8080 loja-graphql:aula07
docker ps
docker logs loja-graphql-aula07
docker stop loja-graphql-aula07
